# Photo Date Organizer · 按拍摄日期整理照片

![Python](https://img.shields.io/badge/Python-3.8%2B-blue) ![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen) ![License](https://img.shields.io/badge/license-MIT-green)

> A zero-dependency Python tool that sorts photos scattered across nested folders into a **Year / Month / Day** hierarchy by shooting date — and never creates empty folders.
>
> 把散落在多层子文件夹里的照片，按**拍摄日期**自动归档到 `根/YYYY/MM/DD` 三级目录。
> **没有照片的年份、月份、日期一律不创建**；日期不可信的照片**不猜测、不丢弃**，隔离到待处理文件夹等待人工确认。
> 想要旧的单层结构？加 `--layout flat` 即可切回 `根/YYYY-MM-DD`。

主程序是**单个 `organize_photos.py`**，只用 Python 标准库，`git clone` 下来就能跑，不需要 `pip install` 任何东西。

---

## 它解决什么问题

一次军训 / 旅行 / 活动下来，照片往往散在根目录和好几个子文件夹里，文件名混乱、还有视频和文档混在一起。这个工具会递归扫描整个目录，读每张照片的 EXIF 拍摄日期，然后在**根目录**下按 年 / 月 / 日 分层归档：

```
整理前                              整理后
军训照片/                          军训照片/
├── IMG_0001.jpg                    ├── 2025/
├── IMG_0002.jpg                    │   └── 12/
├── 说明.txt                        │       └── 25/
├── 子文件夹A/                      │           └── IMG_0100.jpg
│   └── 深层/                       ├── 2026/
│       └── IMG_0003.jpg            │   ├── 01/
├── 跨年_2025/                      │   │   └── 17/
│   └── IMG_0100.jpg                │   │       └── IMG_0101.jpg
└── 子文件夹B/                      │   └── 09/
    └── IMG_0001.jpg  ← 同名        │       └── 01/
                                    │           ├── IMG_0001.jpg
                                    │           └── IMG_0001_2.jpg
                                    ├── _待处理_日期异常/
                                    │   ├── 异常_相机未设时间.jpg
                                    │   └── _隔离清单.csv
                                    ├── 说明.txt        ← 原样保留
                                    └── 子文件夹A/      ← 目录保留
```

`2026/02`、`2026/04`~`2026/08` 这类**没有照片的月份根本不会被创建**。原有的子文件夹、视频、文档保持原位。

## 特性

- **零依赖**：纯标准库实现 EXIF 解析（JPEG APP1 / TIFF / PNG eXIf），不需要 Pillow。装了 Pillow 会自动启用格式增强，但完全可选。
- **三级分层、不建空目录**：默认 `根/YYYY/MM/DD`；只有确实有照片要放进去时才 `mkdir`，移动失败会立即回收刚建好的空目录链。
- **跨平台**：Windows / macOS / Linux 同一份代码；Windows 另有纯 ASCII 的 `run.bat` 可双击、拖拽。
- **不猜测日期**：EXIF 存在但不可信时隔离，而不是悄悄用文件时间蒙混过去。
- **数据安全**：不删除、不覆盖、不解压；同名自动加 `_2`；支持 `--copy` 保留源文件。
- **可预演**：`--dry-run` 只打印结果，一个字节都不动，还能算出同名冲突。
- **可审计**：逐行启动检查、逐张结果、逐条失败原因，并生成 TXT 日志 + Markdown 报告（含真实目录树）+ 隔离清单 CSV。
- **幂等**：重复运行不会重复搬运；隔离目录在后续运行中自动排除。
- **可验收**：自带一键演示与 **16 条自动断言**，双击 `演示测试.bat` 即可跑完并截图。

## 命令行参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `root` | 当前工作目录 | 要整理的文件夹（位置参数） |
| `--layout` | `ymd` | `ymd` = `根/YYYY/MM/DD` 三级分层；`flat` = `根/YYYY-MM-DD` 单层 |
| `--dry-run` | 关 | 只预演，不改动任何文件 |
| `--copy` | 关 | 复制而非移动，源文件保持原位 |
| `--min-year` | `1970` | EXIF 日期允许的最早年份 |
| `--max-year` | 今年 + 1 | 日期允许的最晚年份 |
| `--future-days` | `1` | 允许日期比今天最多晚几天 |
| `--quarantine` | `_待处理_日期异常` | 异常照片的隔离文件夹名 |
| `--no-pillow` | 关 | 禁用可选的 Pillow 增强 |
| `--version` / `-h` | — | 版本号 / 帮助 |

例：放宽到 1950–2030 年、允许未来 7 天、改用单层目录

```bash
python organize_photos.py "D:\老照片" --min-year 1950 --max-year 2030 --future-days 7 --layout flat
```

## 目录结构：年 / 月 / 日

| `--layout` | 归档位置 | 例子 |
| --- | --- | --- |
| `ymd`（默认） | `根目录 / 年 / 月 / 日` | `军训照片/2026/09/01/IMG_0001.jpg` |
| `flat` | `根目录 / YYYY-MM-DD` | `军训照片/2026-09-01/IMG_0001.jpg` |

三条硬规则：

1. **只在真正要移动照片之前才创建目录**。用 `mkdir(parents=True)` 一次性建出 年/月/日 三级，因此某个年份或月份只要没有照片，就根本不会出现。
2. **移动失败立即回收空目录链**。若某张照片被占用导致搬运失败，工具会从最深一级往上删除本次刚建的空目录（遇到非空目录或根目录立即停止），不会留下空壳。
3. **绝不删除你原有的目录**。原始子文件夹即使被搬空了也保留 —— 本工具只新建、只移动文件，不做任何清理删除。

隔离目录始终是根目录下的单层文件夹（如 `_待处理_日期异常/`），不参与分层；其中会放 `_隔离清单.csv`。

> 从旧版升级：旧版生成的是 `2026-09-01/` 这种单层目录。新版默认不再生成它们；如果你仍想要单层结构，加 `--layout flat`。已有的旧目录不会被删除，重复运行时其中的照片会被判为「已在位」而跳过。

## 日期是怎么判定的

按可信度依次尝试，**一旦拿到可信日期就停止**：

| 优先级 | 来源 | 适用 |
| --- | --- | --- |
| 1 | EXIF `DateTimeOriginal` | 相机实际按下快门的时间，最准（JPG / TIFF） |
| 2 | EXIF `DateTimeDigitized` / `DateTime` | 数字化时间 / 文件写入时间 |
| 3 | 文件最后修改时间 | 完全读不到 EXIF 时兜底（截图、PNG、部分 RAW、HEIC） |

可选增强：若环境里装了 `Pillow`，会再用它读一次更多容器格式；**没装也完全不影响使用**。RAW 文件读不到 EXIF 时按文件时间归档，不会被误判为损坏。

### 「日期过于奇怪」怎么处理

这是本工具的核心原则：**EXIF 存在但不可信 ≠ 没有 EXIF**。前者隔离等人工确认，后者才回退文件时间。以下任一情况都会进入隔离文件夹，不做归档：

| 异常类型 | 例子 | 判定 |
| --- | --- | --- |
| 全零 / 占位符 | `0000:00:00 00:00:00` | 相机时间未设置 |
| Unix 纪元哨兵 | `1970-01-01 00:00:00`、`0001-01-01` | 未设置时间的典型默认值 |
| 年份越界 | `1955:03:08`、`2035:07:20` | 超出 `[min-year, max-year]` |
| 日期在未来 | 超过「今天 + `--future-days`」 | 相机时钟被改过 |
| 格式非法 | `not-a-date-string` | 无法解析 |
| 字段不合法 | `2026:13:45 10:00:00` | 月份 / 日期越界 |
| EXIF 段损坏 | 有 APP1 段但 TIFF 头坏掉 | 日期无法解析 |
| 文件损坏 | 0 字节、无法读取 | 疑似占位 / 损坏文件 |
| 文件时间异常 | 1975 年、2031 年 | 兜底时间本身也不可信 |

隔离目录里会生成 `_隔离清单.csv`（UTF-8 BOM，Excel 可直接打开），逐条记录：文件名、原相对路径、保存为、判定原因、原始日期值、日期来源。确认真实日期后，手动拖进对应日期文件夹即可；若确认规则太严，用 `--min-year` / `--max-year` / `--future-days` 放宽后重跑。

> 隔离文件夹在后续运行中会被**自动排除**，不会反复搬来搬去。

## 特殊情况全表

| 情况 | 处理方式 |
| --- | --- |
| EXIF 正常 | 移到 `YYYY/MM/DD`（或 `--layout flat` 下的 `YYYY-MM-DD`），输出里标注来源 |
| 某个年份 / 月份没有照片 | **不创建该层级**，绝不留下空文件夹 |
| 完全读不到 EXIF | 用文件修改时间归档，报告里计入「按文件时间兜底」 |
| 日期可疑（见上表） | 移到 `_待处理_日期异常`，写清单，**不计入整理数** |
| 目标文件夹已有同名文件、内容不同 | 自动加 `_2`、`_3` … 后缀，不覆盖 |
| 目标文件夹已有同名文件、内容完全相同 | 跳过（不产生重复文件） |
| 照片已经在正确的日期文件夹里 | 跳过（幂等，重复运行 0 移动） |
| 文件被别的程序占用 | 跳过该文件，逐行打印原因与修复建议，其余继续；刚建的空目录立即回收 |
| 权限不足 / 只读文件 / 受控目录 | 同上，逐行说明 |
| 路径过长（Windows 260 上限）/ 非法字符 | 自动尝试长路径写法；仍失败则逐行说明并建议移到盘符根目录 |
| 扫描后文件被删掉 / U 盘断开 | 逐行说明，其余继续 |
| 磁盘满 / 只读介质 | 逐行说明 |
| 跨磁盘 / 跨分区移动 | 自动从 `os.rename` 回退到「复制 + 删除源文件」 |
| 图片损坏、解码失败 | 不致命：能读的按 EXIF/文件时间处理，读不了的隔离 |
| 视频 / 文档 / 压缩包 / 日志 | 原地不动，不删除 |
| 原始子文件夹、空目录 | 保留，不清理（即使被搬空） |
| 符号链接 | 跳过，避免把指向外部的文件搬走或造成循环 |
| `.git` / `venv` / `node_modules` / 隐藏目录 | 扫描时排除 |
| 压缩包里的照片 | 不解压；会提示先解压再运行 |
| `Ctrl+C` 中断 | 已完成的移动保留，重新运行不会重复处理 |
| 窗口一闪而过 | 每次运行强制写 `整理工具_运行记录.txt`（写不进就落 TEMP） |

支持扩展名：`.jpg .jpeg .jpe .jfif .png .heic .heif .tif .tiff .bmp .gif .webp .avif` 以及常见 RAW（`.cr2 .nef .arw .dng .raf .orf .rw2 …`）。

## 跑不通怎么办

**1. 先看启动检查。** 每次运行都会逐行打印 7 项检查结果：Python 版本 → 目标目录存在 → 日期参数自洽 → 目录可读 → 目录可写 → EXIF 组件就绪 → 递归扫描结果。任何一项失败都会按「检查项 → 原因 A/B/C → 修复建议 1/2/3」逐行展开。

**2. 看运行记录。** 目标目录里的 `整理工具_运行记录.txt` 是启动瞬间就写的，内容随运行实时追加；就算窗口一闪而过也能查。若目标目录不可写，会自动改存到系统 TEMP 目录。

**3. 退出码。**

| 退出码 | 含义 |
| --- | --- |
| `0` | 正常完成（含 0 张照片、全部已在位） |
| `1` | 至少一张处理失败，但其余已完成 |
| `2` | 启动检查失败，没有移动任何文件 |
| `130` | 用户 `Ctrl+C` 中断 |

**4. 常见现象**

| 看到什么 | 怎么办 |
| --- | --- |
| 提示 `Python 不是内部或外部命令` | 装 Python 3.8+，安装时勾选「Add python.exe to PATH」 |
| 中文输出是乱码 | 脚本已自动设置控制台 UTF-8；若重定向到文件，用 UTF-8 打开 |
| 一张都没找到 | 检查扩展名、照片是否还在压缩包里（本工具不解压） |
| 归到的日期不对 | 该照片没有 EXIF，用了文件时间；用 `--dry-run` 看「日期来源」 |
| 想要单层 `2026-09-01` 而不是三层 | 加 `--layout flat` |
| 大量照片被隔离 | 规则太严，用 `--min-year` / `--max-year` / `--future-days` 放宽 |
| 权限 / 占用报错 | 关掉看图软件与预览窗格，或把文件夹复制到桌面普通目录再跑 |
